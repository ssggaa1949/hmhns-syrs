SyRS 简介

System Requirements Specification · 表 5-1 第 1 章

1.1 目的

在作业 2 的 BRS / StRS 基础上，从技术视角把运行概念转换为方案域的系统需求：明确系统必须执行的功能、达到的性能、满足的接口与质量特性，并据此形成初始架构与安全方案，作为后续设计定义的基线。

1.2 范围

  • 范围内：神经信号采集、边缘解码控制、执行器驱动、感觉反馈、运行模式管理、状态监测、数据追溯，以及贯穿全程的安全监控。
  • 范围外：植入物材料配方与芯片版图设计、云端大模型训练过程、医院信息系统（HIS）内部业务流程。

1.3 系统边界与外部接口

外部实体交互要素接口方向
人体神经系统（佩戴者）神经电信号 / 刺激反馈 / 生理状态双向：采集 ↔ 反馈
外部执行器（假肢 · 外骨骼 · 机械臂 · 光标）运动指令 / 执行状态系统 → 执行器；状态回传
治疗师 / 安全监督者控制参数 / 训练指令 / 告警监督层 ↔ 控制器

运行环境（家庭 · 康复室 · 作业现场）电气 / 电磁 / 温度 / 佩戴姿态环境约束输入

功能需求

System functional requirements · SYS-F
SYS-F-01系统应通过电极阵列持续采集佩戴者的神经 / 肌电信号，并在信号丢失或电极阻抗异常时给出可辨识告警。感知采集
SYS-F-02系统应对原始信号完成滤波、工频陷波、伪迹剔除与特征提取，输出可供解码的特征向量。边缘控制
SYS-F-03系统应在本地完成运动意图解码，输出意图类别与置信度；置信度不足时不得强行驱动执行器。边缘控制
SYS-F-04系统应把解码意图映射为执行器动作（假肢关节角度、外骨骼力矩、机械臂位姿或光标位移），并按当前模式约束动作范围。执行端子系统
SYS-F-05系统应通过电刺激 / 振动 / 压力反馈通道回传触觉、位置与负载感觉，构成闭环。反馈子系统
SYS-F-06系统应支持校准、康复训练、自主增强、安全待机、紧急断开五种运行模式，并允许监督者在模式间切换。模式管理
SYS-F-07系统应持续监测电极阻抗、电池电量、处理器温度、执行器状态与信号质量，并在异常时进入降级或安全待机。健康诊断
SYS-F-08系统应记录运行日志（意图、置信度、动作、反馈、告警与人工干预），支持事后追溯与导出。数据追溯

接口需求

Interface requirements · SYS-I

4.1 用户接口（HMI）

  • 显示当前运行模式、解码置信度、电量、信号质量与告警状态。
  • 提供佩戴者可触及的物理紧急断开按钮，优先级高于任何软件控制。
  • 治疗师工作台可查看实时曲线、调整助力与反馈增益、导出康复报表。

4.2 硬件接口

  • 电极阵列：标准化导联接口，支持阻抗检测与单点断线识别。
  • 执行器：数字运动总线（角度 / 力矩 / 状态回传）。
  • 反馈刺激器：双通道刺激参数（幅度 · 频率 · 脉宽）可配置。

4.3 软件接口

  • 与云端平台同步脱敏特征与模型权重；本地模型可离线运行。
  • 日志与报表以开放格式导出（CSV / PDF）。

4.4 通信接口

  • 体内 / 体表与边缘盒之间采用无线或短距有线链路，链路加密。
  • 边缘盒与云端之间采用 TLS；断网时本地闭环不受影响。

质量特性与运行需求

Quality & operational requirements
质量特性系统要求
安全性不得发生超出人体自主意志的强制动作；具备硬件级紧急断开与安全联锁（详见第 8 节 STPA）。
保密性神经数据端到端加密；云端仅保存脱敏特征；用户可导出并要求删除全部个人数据。
可靠性单点电极断线、链路中断、执行器异常时系统降级到安全待机，不得进入失控状态。
可用性 / 人因佩戴者无需刻意学习即可完成基础控制；告警以视觉 + 触觉双通道呈现；长时间佩戴无明显异物感与热感。
可维护性电极、边缘盒、执行器可独立更换；算法支持灰度 OTA 与一键回滚。

运行需求（各模式行为）

  • 校准模式：仅采集与记录特征，不驱动执行器；由治疗师确认标定结果后退出。
  • 康复模式：治疗师监督下闭环训练，助力与反馈增益可调。
  • 自主增强模式：佩戴者独立使用，动作范围受安全边界约束。
  • 安全待机：低功耗监测，执行器保持当前安全姿态，不主动输出动作。
  • 紧急断开：切断机器通路，回到原生神经状态，事件入日志。
6

设计约束

Design constraints
  • 植入 / 体表部件满足 ISO 10993 生物相容性，预期使用寿命 ≥ 10 年。
  • 医疗线按三类医疗器械（NMPA / FDA）流程接受注册与监管审查。
  • 神经数据处理受个人信息保护与医疗数据合规约束。
  • 边缘盒功耗、体积、重量须满足日常佩戴；执行器力矩不得超过佩戴者肢体生理极限。
  • 所选解码算法须可离线推理，不依赖持续联网。

基于 STPA 的安全分析

System-Theoretic Process Analysis · 四步法

8.1 第 1 步：损失、危害与安全目标

编号事故 / 损失（Loss）潜在危害（Hazard）
L-1佩戴者身体损伤非自主动作超出肢体生理极限，造成拉伤、骨折或挤压伤
L-2神经 / 组织损伤刺激参数超限、电极过热或错位，引起神经或皮肤损伤
L-3设备失控 / 跌落执行器在断电或异常时突然松脱、坠落或误动作
L-4隐私 / 自主权受损神经数据泄露，或机器动作绕过佩戴者主观意志
L-5过度依赖与二次伤害长期使用后原生神经功能退化，或误信低置信度解码

高层级安全约束（安全目标）

  • SC-1：任何机器动作必须处于佩戴者自主意志可随时中断的范围内。
  • SC-2：刺激与运动参数不得超过生理安全边界。
  • SC-3：任何单点失效不得导致执行器失控或松脱。
  • SC-4：神经数据未经授权不得离开本地受控环境。

8.2 第 2 步：安全控制结构

在 7.1 顶层结构上叠加独立于主控制器的安全监控子系统：直接读取传感器与执行器状态，拥有绕过主控制器的紧急断开权限。

8.3 第 3 步：不安全控制动作（UCA）识别

编号控制动作不安全情形关联危害
UCA-01输出运动指令在佩戴者未形成明确意图（低置信度）时仍下达动作指令L-1, L-3
UCA-02输出运动指令动作幅度 / 力矩超过肢体生理安全边界L-1, L-2
UCA-03未输出应有的安全约束检测到异常但未进入安全待机或急断L-3
UCA-04刺激反馈刺激幅度 / 频率 / 脉宽超限，造成组织或神经损伤L-2
UCA-05模式切换在康复训练中未经治疗师确认直接切入自主增强模式L-1
UCA-06数据上传未脱敏的原始神经数据被上传至云端L-4
UCA-07执行器保持 / 释放断电或链路中断时执行器突然松脱，导致部件坠落L-3
UCA-08反馈提示告警缺失或延迟，佩戴者 / 治疗师未察觉风险状态L-1, L-5

8.4 第 4 步：因果场景 → 安全需求

UCA可能因果场景派生安全需求
UCA-01解码模型在信号受伪迹干扰时误判；置信度阈值未参与动作使能SAF-REQ-01 置信度 < 0.6 时禁止驱动执行器
UCA-02动作映射未绑定个人生理限位；不同佩戴者参数混用SAF-REQ-02 动作范围按个体限位硬约束，超限自动限幅
UCA-03主控制器自检逻辑缺陷，异常未上报；安全通道与主控共用单点SAF-REQ-03 独立安全监控通道，可旁路主控触发安全待机 / 急断
UCA-04刺激参数软件可配置，缺少硬件上限保护SAF-REQ-04 刺激幅度 / 脉宽设硬件级上限，超限自动切断
UCA-05模式切换缺少监督者确认环节SAF-REQ-05 康复 → 增强模式切换须治疗师确认并记录
UCA-06上传链路未区分原始数据与脱敏特征；本地脱敏失效SAF-REQ-06 原始神经数据不出本地，云端仅接收脱敏特征
UCA-07执行器依赖持续通电保持姿态，断电即失能SAF-REQ-07 断电时执行器机械锁止在安全姿态
UCA-08仅单通道视觉告警；佩戴者注意力集中在任务上SAF-REQ-08 告警采用视觉 + 触觉双通道，超时未确认自动降级

安全架构

Safety architecture

安全需求分配到独立安全监控子系统，形成"主控 + 独立安全通道"双层结构：主控负责功能闭环，安全监控负责边界守护与急断，二者物理与逻辑解耦，避免单点共因失效。

安全机制实现方式对应安全需求
置信度熔断解码置信度实时比对阈值，低于阈值禁止动作使能SAF-REQ-01
生理限位硬约束个体动作 / 刺激限位写入硬件或不可绕过的配置层SAF-REQ-02 / 04
独立看门狗独立监测主控心跳、传感器与执行器状态，异常旁路急断SAF-REQ-03
硬件紧急断开物理按钮 + 安全联锁，切断机器通路，回到原生神经状态SC-1 / SAF-REQ-03
断电保持执行器机械抱闸 / 锁止结构，失电不松脱SAF-REQ-07
双通道告警视觉提示 + 触觉提醒，超时未确认自动进入安全待机SAF-REQ-08
数据隔离本地存储与加密上传分离，云端仅接收脱敏特征SAF-REQ-06 / SC-4

安全层级（自上而下）

  1. 监督层：治疗师 / 安全监控掌握模式与参数审批权。
  2. 功能层：主控制器完成采集—解码—执行—反馈闭环。
  3. 安全层：独立安全监控通道持续守护边界，必要时旁路主控急断。
  4. 硬件层：限位、联锁、抱闸、物理急断按钮构成最后一道防线。
